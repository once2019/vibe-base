# 治理复盘细则

> 本文件是复盘的正本：执行流程、存量项目自查（8 问）、再复盘信号清单、产出物格式。
> 反模式的实测证据链（模板为何长成这样）属技能维护记录，不在项目内分发；项目自己的复盘证据存 `docs/design/`。
> 相关：`l1-maintenance.md`（规则修订流程）、`decision-writing.md`（决策与索引写作）。

## 复盘流程（五步）

1. **收集症状**（只认运行痕迹）：
   - 按下方「存量项目自查（8 问）」逐问实测作答；
   - 实测手段：记忆文件行数与最长行实测（对照双预算）、决策索引行数与最近 3 条质量、同主题决策追记计数（grep「追记」）、疑似分叉规则的全文对比、近期会话收尾三件套留痕抽查。
   - 知识健康三查：文档间矛盾（两处对同一事实的陈述冲突）、过期引用（被推翻/取代的决策仍被其他文档引用其旧结论）、孤儿文档（无任何入链且近期无更新）。
2. **列清单**：每条症状按「问题 → 证据 → 改法」格式登记；无证据的体感不入清单（"感觉 Agent 总忘事"不是证据，"handoff 缺失 3 次"是）。
3. **逐条裁决**：每条独立裁决为 采纳 / 否决 / 改写，写明理由；相抵的规则对（文本规则 vs 实测写法）在此调和——终态语义保留，写法取实测可行的那个。
4. **统一修订**：裁决完的改法直接修改规则文件，每处标注变更日期与原因；改模板走 `l1-maintenance.md` 修订流程（先决策记录后改文件）。
5. **治理收口**：决策记录与索引同步（写作细则见 `decision-writing.md`）；docs 与代码同一次提交；展示验证输出。

## 存量项目自查（8 问）

1. AGENTS.md 有没有单行超 200 字符？参数级细节是否 `--help` 可查？
2. context.md / handoff.md 行数"达标"时，最长行多少字符？
3. "更新即重写"与并行会话下的实际写法是否相抵？
4. 决策超过 20 条后，"修改前先搜索"实际执行成本多高？有没有索引？
5. 被取代的决策，其状态行真的标了吗？追记有没有格式规范？
6. Ask-first 事项能不能在一处看全？
7. handoff 里的 pid、时限纪律过期后谁清理？
8. 新会话起步必读内容，最近一个月涨了多少？

## 什么时候该再复盘

出现任一信号即重跑一轮「问题 → 证据 → 改法」清单 + 逐条裁决：

- 任一记忆文件超双预算，或为守行数开始写 200+ 字符长行
- 决策索引超过一屏（~50 条）仍未建立或停止维护
- 同一主题的决策记录被追记超过 3 次（说明该"另建新条"了）
- 同一条规则在两处出现且表述开始分叉
- 同一条规则在两次复盘里以不同措辞重现（前次改法未落到可判定动作，须重判而非再补条款）
- 收尾三件套（context / progress / 决策记录）开始被跳过或敷衍
- 文档间出现矛盾陈述，或被取代的决策仍被引用（知识健康失效）

## 产出物格式

- 固定为「问题→证据→改法」表格，列：`# / 反模式 / 实测证据 / 改法（已固化到哪份文件）`。
- 复盘全文（含背景与证据）存 `docs/design/` 下的复盘文档，头部标注变更日期与原因；改法已固化的部分更新进规则本体，复盘文档保留证据链。
- 本轮若修订了信号定义，直接改本文件的「什么时候该再复盘」节——它是唯一正本，不再两处同步。

## 原则

- 反模式不可怕，可怕的是只有体感没有证据、只有清单没有裁决。
- 复盘是治理体系唯一的自我修正通道：发现规则被反复违反，先修规则再按新规则执行，不允许"下不为例"。
- 8 问与信号清单只在本文件维护；`AGENTS.md` 只留指针，不复述清单。
