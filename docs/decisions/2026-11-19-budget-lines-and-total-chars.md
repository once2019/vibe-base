# 双预算改成「行数 + 总字符」，删掉单行字符上限

- 日期：2026-11-19
- 状态：已生效
- 相关模块：`AGENTS.md` §5、`docs/governance/memory-writing.md`、`scripts/foreman.py`（`governance-budget`）

## 决策内容

三条预算从「行数上限 + 单行字符上限」改为「行数上限 + 总字符上限」：

| 文件 | 行数 | 总字符 |
| --- | --- | --- |
| `AGENTS.md` | ≤100 | ≤10000 |
| `docs/memory/context.md` | ≤40 | ≤3000 |
| `docs/memory/handoff.md` | ≤60 | ≤4000 |

`doctor` 的 `governance-budget` 检查同步改为按总字符判定。

## 选择理由

单行上限的真实成本出现在 2026-11-19 这次会话：`context.md` 41 行超预算，为压回 40 行重写整份文件（提交 `b14f6e6` 是纯记账），而超出的那行只是把一个条目写完整，信息没有多余。字符上限本身想防的是「行数达标但每行塞满」，这个风险用总字符数一次算总数就能堵住，而且判据更简单：不用逐行量。

三个数字的取法：`AGENTS.md` 现状 95 行 / 5527 字符，storyboard 99 行 / 6524 字符，10000 给两边都留约 50% 余量；context 与 handoff 按同样口径取现状的两倍左右。

## 被否决的替代方案

| 方案 | 否决原因 |
| --- | --- |
| 保留单行上限、提高阈值到 300 | 仍是逐行判，仍会为了一个长句重写整段；阈值本身没有推导依据 |
| 只留行数上限 | 「40 行 × 每行 500 字符」= 20000 字符，等于取消预算 |
| 按总字节数判 | 中文与英文的字节比不同（CJK 3 字节），跨语言项目没有可比性 |

## 影响范围

- 涉及文件/模块：`AGENTS.md` §5、`memory-writing.md`、`foreman.py` 常量与 `doctor` 检查、两份记忆文件的头部引用
- 兼容性影响：已初始化项目需同步 §5 那一行与 `foreman.py`；storyboard 现状 99 行 / 6524 字符仍在预算内
- 后续约束：新增预算维度前先答「现有两个维度漏了什么具体情形」
