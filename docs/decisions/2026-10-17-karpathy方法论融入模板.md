# karpathy 方法论融入模板

- 日期：2026-10-17
- 状态：已生效
- 相关模块：`skills/vibe-init/assets/AGENTS.md` §3、`skills/vibe-governance/references/l1-maintenance.md`、三个 SKILL.md

## 决策内容

将 karpathy-guidelines 方法论融入模板正本，分两层：①四条行为规则提炼为模板语言补进常驻层 AGENTS.md §3 空位（假设显性化、最小代码、外科手术式修改、任务转译为可验证目标），使任何 Agent 读 AGENTS.md 即被约束、无需技能触发；②三个元设计（失败模式驱动、self-check 验证方式、tradeoff 声明）作为元规则固化进 vibe-governance 的 l1-maintenance 收录铁律，并立即为三个 SKILL.md 补 tradeoff 声明。

## 选择理由

- 行为层真空位：模板 §3 原只覆盖风格跟随与可判定性，简单性、修改边界、假设管理无条款；karpathy 四条恰补此空，且经真实项目本地验证。
- 元设计同构：失败模式驱动 = 模板复盘方法论（问题→证据→改法）；self-check 问句 = 可判定性红线的问句形态；tradeoff 声明补齐"规范假装零成本"的缺陷——融入是收敛既有体系，非引入第二体系。
- 分层落位符合触发可靠性模型：编程行为须无条件生效 → 常驻 AGENTS.md；规则演化由 §8 指针条款拉起 vibe-governance 时强制 → references；tradeoff 在读规范时才相关 → SKILL.md。

## 被否决的替代方案

| 方案 | 否决原因 |
| --- | --- |
| 照抄 karpathy 四条原文入模板 | 与模板语言/可判定风格不一致；部分条款与既有红线重复（匹配既有风格已由"跟随多数用法"覆盖） |
| 只融三个元设计不融四条规则 | 直接指导编程工作的是行为规则本身，元设计只保证规则质量；§3 空位依旧 |
| 新增第四个技能承载 | 违背"常驻层无条件生效"诉求；行为规则不属按需范畴 |

## 影响范围

- 涉及文件：assets/AGENTS.md §3（+4 行）；l1-maintenance.md（收录铁律 +3 条元规则）；三个 SKILL.md（各 +1 行 tradeoff）；`~/test` 同步。
- 兼容性：既有红线语义不变；AGENTS.md 总行数 ~85（≤100 预算内）。
- 后续约束：ashare-lake 本地 karpathy-guidelines skill 不动（出处正本）；模板内不复制其原文，只留提炼条目；新增行为规则一律按 l1-maintenance 元规则办理。
