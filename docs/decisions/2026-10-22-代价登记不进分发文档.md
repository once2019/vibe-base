# 代价登记不进分发文档

- 日期：2026-10-22
- 状态：已生效
- 相关模块：`skills/vibe-base/assets/docs/governance/l1-maintenance.md`、`docs/governance/l1-maintenance.md`、`skills/vibe-base/assets/docs/design/governance-retrospective.md`、`docs/design/governance-retrospective.md`、`docs/decisions/2026-10-22-复盘经验进治理体系.md`

## 决策内容

撤销「规则代价与豁免集中登记于 `docs/design/` 复盘文档改法列」的安排：代价在规则评审时记于决策记录，L1 只写规则本体与适用边界，边界须有真实误执行证据才写。复盘文档回归证据链，不再充当代价台账；原 `docs/design/2026-10-22-执行失败模式复盘.md` 删除后不恢复、不进模板 assets。

## 选择理由

- 消费者错位：tradeoff 铁律的读者是规则设计者与评审者（判断这条规则值不值得进 L1），不是执行规则的 Agent；把评审用的台账随模板分发，等于把史料塞进 bootstrap 面。
- 增量复核为零：原文档 6 条「代价 / 豁免」逐条核对——2 条为空（fail-visible、修订留指针），2 条是 Agent 本来就不会犯的自然豁免（改注释免复检、已有测试免观测），1 条已被同节条款覆盖（L30「桩测试与样例只证明分支」），1 条净负（「紧急止血可先加分支」给永久后门，且引入模板未定义的「技术债登记」概念）。按 `l1-maintenance.md` 收录铁律第 1 问，六条全部答「删掉不会犯错」。
- 外移的预算前提不成立：原决策 `2026-10-22-复盘经验进治理体系.md` 以「单行逼近 200 字符」为由把代价移出 L1；实测该文 6 条规则在模板 `AGENTS.md` 中占 57 / 94 / 71 / 61 / 59 字符，全文件最长行 171 出现在 §5 记忆协议，与这 6 条无关。行内空间充裕，外移缺乏预算理由。
- 规则刚性：豁免是显式的「允许不做」，会把可判定规则降级为可辩解规则；代价信息无此副作用，但它服务评审而非执行。

## 被否决的替代方案

| 方案 | 否决原因 |
| --- | --- |
| 把该复盘文档收进 `assets/docs/design/` 作为分发版代价台账 | 凭证只服务规则制定者；进 assets 即进每个新项目的首个 bootstrap 面，与 §5「起步只读索引摘要」相抵 |
| 把 6 条豁免写回 `AGENTS.md` 行内 | 六条均无增量价值；第 5 条会引入「技术债登记处」这一模板内无落点的新概念 |
| 保留 `l1-maintenance.md:12` 的「改法列」措辞、只删文档 | 该措辞指向一个复盘格式规范从未定义的列（`governance-review.md` 表列为证据+改法），留着必然被下一个维护者再问一次 |
| 让 `governance-review.md` 复盘表增加「代价 / 豁免」列 | 复盘产出物定位是「问题→证据→改法」，代价属评审对话与决策记录，两类信息生命周期不同，合表会迫使证据链维护者替规则评审兜底 |

## 影响范围

- 涉及文件/模块：`docs/governance/l1-maintenance.md`（含 assets 副本）、`docs/design/governance-retrospective.md`（含 assets 副本，承接一条再复盘信号）、`docs/decisions/2026-10-22-复盘经验进治理体系.md`（引用的已删路径清理，状态行改部分取代）、`docs/decisions/README.md`
- 兼容性影响：无破坏性变更。`AGENTS.md` 88 行不变；复盘表列定义不变。
- 后续约束：新增行为规则时，代价与豁免在决策记录的选择理由中评审，L1 不复述；只有出现真实误执行证据时，才把适用边界写进规则行内。
