# AGENTS.md §3 增「用户意图先复述再动手」

- 日期：2026-11-18
- 状态：已生效
- 相关模块：`AGENTS.md` §3、`skills/vibe-base/assets/AGENTS.md`

## 决策内容

§3 在「沟通受控」之后新增一条：

> 用户意图先复述再动手：把指令复述成「改哪个文件或行为 + 判据」一行，写不出或有两种以上解读就先问，一次一问。用户说「感觉/好像/是不是」时要的是观测与判断，不是改规则；一句话指令只做那一件事。

## 选择理由

触发的事实：同一个会话里连续两次方向错——用户说「worker 完成的比单会话好，不知道是不是错觉」，被当成「要写一条规则」直接落地了细则；另一处把一张「worker 活着」的截图读成「worker 卡住要止损」，还想替它做技术判断。两次都不是不理解术语，是把一句感想、一张截图当成了指令，然后自己补全了没说的部分。

§3 原有的「存在多种解读时全部列出，不清楚即停下询问」埋在第一性原理那条的尾部，管的是设计与规则推导，不覆盖「用户这句话要不要动手、动到什么程度」。这条补的是那个缺口，判据是两个动作而不是一种态度：

- 复述成「改哪个文件或行为 + 判据」一行，写不出就是没想清，先问。
- 一次一问：多个问题一起抛，用户会挑好答的答，剩下的沉默被当成默认。

「感觉/好像/是不是」的判据来自这两次事故的共同形状：这类句式带的是不确定，要的是观测与判断，不是流程变更。一句话指令只做那一件事，是对「顺手扩成方案」的约束——扩出去的部分没人要，返工成本由用户承担。

## 被否决的替代方案

| 方案 | 否决原因 |
| --- | --- |
| 主管判断 worker 状态时必须先问人类 | 把「止损/重派」从 §4 的「主管拍板」挪进 Ask-first，而 §4 清单封闭；「拿不准」不可判定；§3 第一性原理已覆盖「结论依赖外部系统行为先跑最小观测」 |
| 只写进 `orchestration.md` | 那份只在编排时读，普通编码会话读不到；这条对两种会话都成立 |
| 每次回复都复述并等确认 | 与「人类明确指令优先」相抵，正常指令变成两轮；只在写不出复述或有多种解读时触发 |
