# 守卫的生命周期：准入 → 分档 → 举证 → 退出

- 日期：2026-11-19
- 状态：已生效
- 相关模块：`docs/governance/coding-discipline.md`（守卫的生命周期）、`scripts/foreman.py`（派工单红线）
- 合并：`2026-11-19-normalization-boundary-criterion`（归一边界）、`2026-11-19-validation-ladder-normalize-retry-block`（降级阶梯）为本节的前两步

## 决策内容

把分散在两条决策里的判据合成一个生命周期，四步各有可判定判据：

1. **准入**：三问缺一不收 + 归属表；准入判据与退出判据是同一个实验——「关掉它，谁会发现？」
2. **分档**：每条校验落地时声明属于归一 / 回喂重试 / 阻断 / 静默哪一档，声明不出来按静默。
3. **举证**：既有守卫挡路时，agent 可以报告「它指不出真实故障」，不得自行放宽或在消费点加兼容分支绕过；放宽由主管裁决并落决策记录。边界一句话：风格跟惯例，守卫要证据。
4. **退出**：判据是对照实验「关掉它谁会发现」，不是触发率。三种结局三种处置（测试红→留并核对位置；产物变了没人发现→降归一或删；产物变了用户看得见→留并核对分档）。

## 选择理由

这现象有五个互相独立的机制，一条规则治不了：

| 机制 | 表现 | 对应步骤 |
| --- | --- | --- |
| 容忍成本摊到消费点 | 同一字段在 N 个模块各自兜底，删不动 | 准入 + 归一边界 |
| 违规处理不分档 | 同义词差异也走整次重试 | 分档 |
| 门只进不出 | 无人负责删，删门有个人风险 | 退出 |
| Agent 默认服从既有结构 | 无用守卫被当范本复制 | 举证 |
| 放宽无记录 | 宽松与严格来回摆，成本不可见 | 分档第 4 条 |

其中「退出」是最缺的一环：准入三问只管进门，出清没有任何通道。而触发率是坏判据，两个方向都会骗人——实测 `sceneView` 闭集校验每次触发只挡住 `rearview` 一个同义词（本可归一），反过来低频灾难恰恰不触发。能同时判准入与退出的只有「关掉它谁会发现」。

本次对照实验的方法也值得固化：关掉一条守卫，跑一次真实输入，看三种结局。这比读代码判断「这条有没有用」便宜，比看触发计数准确。

## 被否决的替代方案

| 方案 | 否决原因 |
| --- | --- |
| 只写退出判据不写举证义务 | 举证缺位时 agent 的默认动作是绕过（加兼容分支），绕过留下的沉积比守卫本身贵 |
| 用触发率/命中率做退出判据 | 高触发可能是纯同义词，零触发可能是低频灾难保险；两个方向都误判（实测） |
| 建定期清理流程 | 造流程本身就是新守卫；改为动作发生时（重构、换线、给同一处加第二条校验）顺手做一次 |
| 一次性清理全库存量守卫 | 误删代价高于维持现状；只有挡了你路的那一处才轮到做实验 |

## 影响范围

- 涉及文件/模块：`coding-discipline.md`（一节重写）、`foreman.py` 派工单红线（+1 条）、测试 2 项
