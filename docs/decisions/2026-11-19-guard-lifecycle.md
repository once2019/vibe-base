# 守卫的生命周期：准入 → 分档 → 举证 → 退出

- 日期：2026-11-19
- 状态：已生效（合并并取代 `2026-11-19-normalization-boundary-criterion`、`2026-11-19-validation-ladder-normalize-retry-block`）
- 相关模块：`docs/governance/coding-discipline.md`（守卫的生命周期）、`scripts/foreman.py`（派工单五轴·架构轴 + 红线）、`AGENTS.md` §3

## 决策内容

外部输入不稳定是事实（模型、用户、第三方）。容忍它有两种付法：在归一层付一次，或在每个消费点各付一次。后者不可逆，所以守卫的存废必须有据。四步，各有可判定判据：

**1 准入**：三问缺一不收——防的真实故障发生在哪次运行 / 用户看不看得见 / 能不能改成结构或测试。归属表定位置（内部一致性进测试、外部输入进运行时、偏好进提示词、防遗忘进 tests 或 CI）。准入判据与退出判据是同一个实验：**关掉它，谁会发现？** 三问只用于新增。

**2 分档**：每条校验落地时声明属于哪一档，声明不出来按静默。能一一映射的词汇差异**归一**不重试；必须模型理解才能改的语义错误**回喂重试**且 reason 给出期望值；只有产物必崩才**阻断**。

**3 举证**：既有守卫挡路时报告「它指不出真实故障」，由人类或主管裁决，不许自行放宽也不许就地绕开。边界一句：风格跟惯例，守卫要证据。

**4 退出**：判据是对照实验「关掉它谁会发现」，不是触发率。三种结局三种处置：测试红→留下并核对该不该挪到测试侧；产物变了没人发现→降成归一或删；产物变了用户看得见→留下并核对分档。

## 选择理由

这现象有五个互相独立的机制，一条规则治不了：

| 机制 | 表现 | 对应步骤 |
| --- | --- | --- |
| 容忍成本摊到消费点 | 同一字段在 N 个模块各自兜底，删不动 | 准入 + 归一边界 |
| 违规处理不分档 | 同义词差异也走整次模型调用 | 分档 |
| 门只进不出 | 无人负责删，删门有个人风险 | 退出 |
| Agent 默认服从既有结构 | 无用守卫被当成范本复制 | 举证 |
| 放宽无记录 | 宽松与严格来回摆，成本不可见 | 分档第 4 条 |

三组实测支撑：

- **扩散**：storyboard `app` + `pipeline` 25,077 行里，`sceneIds` 一个字段在 16 个模块被各自 `.get(...) or []` 读取并各自去重排序；`_norm` 类小函数 8 个以上各写一份；`.get(` 2285 处、`or []/{}` 1007 处、`isinstance(` 302 处。
- **不分档的代价**：换线后第一次真实运行（项目 61，4 场）2 场需重试，一次是 `sceneView='rearview'` 不在闭集 `['front','reverse']`（语义唯一，只是词不同，却付了整次调用），一次是表外角色 8 处（真语义错误，回喂候选名单即修好）。
- **重试的效果取决于 reason 的信息量**：`pipeline/writer/contract.py` 注释记着——只报「不在闭集」，三次重试全耗在猜简称上；改成把闭集喂回去才解决。

退出这一环最缺：准入只管进门，出清没有通道。而触发率是坏判据，两个方向都骗人——`sceneView` 那条每次都触发，却只挡住一个同义词（本可归一）；反过来低频灾难恰恰不触发，判成冗余删掉就是事故。能同时判准入与退出的只有「关掉它谁会发现」，它比读代码便宜、比触发计数准确。

## 被否决的替代方案

| 方案 | 否决原因 |
| --- | --- |
| 禁止消费点写 `.get(k) or 默认` | 那是缺省语义不是猜形状，禁了会逼出更绕的写法 |
| 违规一律重试 | 词汇差异要付整次调用；实测一半重试是纯同义词 |
| 违规一律归一 | 语义错误无法一一映射（`弗兰克` 不在名单，归一成谁都是错） |
| 先放宽闭集 | 通过更多形态会让下游兼容层变厚，成本从模型端搬到代码端且不可逆 |
| 只写退出不写举证 | 举证缺位时默认动作是绕过，绕过留下的沉积比守卫本身贵 |
| 用触发率做退出判据 | 高触发可能是纯同义词，零触发可能是低频灾难保险 |
| 建定期清理流程 | 造流程本身就是新守卫；改为动作发生时（重构、换线、加第二条校验）顺手做一次 |
| 一次性清理全库存量守卫 | 误删代价高于维持现状；只有挡了你路的那一处才轮到做实验 |
