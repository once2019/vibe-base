# 技能包只发规范与原则，原因归决策记录

- 日期：2026-11-19
- 状态：已生效
- 相关模块：`skills/vibe-base/` 全部规范文档（`SKILL.md`、`README.md`、`assets/AGENTS.md`、`assets/docs/governance/`）、`tests/test_skill_docs.py`

## 决策内容

技能分发的规范文档只写**做法与判据**。原因、推导、历史过程一律不写，归 `docs/decisions/`（技能仓自身）与项目的决策记录。

约束三处：

- `l1-maintenance.md` 收录铁律加一条「规范不带论据」；代码注释与决策记录不受此限。
- `tests/test_skill_docs.py` 扫 `SKILL.md`、`README.md`、`assets/**/*.md`，命中带日期的实测记述、事故编号、代价陈述即失败。
- 层的分工写进 `README.md`：常驻层放红线与目录，细则层放做法与判据，决策库放理由与被否决的方案。

## 选择理由

规范文档有两个读者：执行规则的 Agent 与修改规则的维护者。前者只需要"做什么、怎么判定"，论据会挤占他的上下文并诱导他把叙述当依据；后者要的是完整的取舍链，那是决策记录的职责。两者写在同一份文件里，规范会被论据稀释到无法快速核对。

改前的实际情况：`coding-discipline.md` 的守卫一节里混着 storyboard 的实测数据（`sceneView` 每次触发只挡一个同义词），`orchestration.md` 有十余处「2026-11-16 实测 T-036」式记述，`README.md` 一半篇幅是「问题从哪来」与「理论支撑」。这些内容在决策库里都有正本。

## 被否决的替代方案

| 方案 | 否决原因 |
| --- | --- |
| 规范与理由同文件、理由折叠 | 折叠对 Agent 无效，它读全文；维护者也不会展开 |
| 只靠评审时人工把关 | 上一轮我自己就把实测数据写进了规范，靠自觉无效 |
| 只写规则不写判据 | 判据是规范的一部分（「每条规则必须可判定」），删的是判据之外的解释 |
| 把理由全删不迁移 | 决策库缺正本时理由会丢；先确认决策条目，再删规范里的复述 |

## 影响范围

- 涉及文件：`skills/vibe-base/` 下 9 份文档 + 派工单与 worker prompt 文本 + 1 个新测试
- 兼容性影响：无代码行为变更；`foreman.py` 里派工单与 prompt 的措辞缩短，测试同步更新断言
- 后续约束：新增规范只写做法与判据；论据先进决策记录，规范里留指针；`tests/test_skill_docs.py` 是这条规则的机械守卫
