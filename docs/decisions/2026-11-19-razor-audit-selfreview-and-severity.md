# 剃刀审计：自审归一处、严重度收成两档

- 日期：2026-11-19
- 状态：已生效
- 相关模块：`skills/vibe-base/assets/scripts/foreman.py`、`docs/governance/orchestration.md`

## 决策内容

两处减法，按「删掉它，Agent 会犯什么错？」判定：

1. **自审细节只留一处。** `worker_prompt` 原来把机械四项、五轴、反证三个步骤的全文写了一遍，`brief_text` 的「自审」节又写一遍，两份都注入 worker。改成 prompt 只留指针「按派工单「自审」节的步骤做」，细节归 brief。
2. **严重度从四档收成两档**：`必须改` / `建议`，删 `阻断`（与「必须改」同义，差别只在合并动作，而 merge 本来就不许跳过必须改）与 `备查`（只告知，不产生动作）。

## 选择理由

自审重复不是篇幅问题，是两个实际成本：**上下文体积**（每轮都要读，实测小仓 3.2 秒/轮、storyboard 7.7 秒/轮，上下文越大越慢）和**漂移风险**（本会话跑变异脚本打偏位置，把 prompt 那份自审弄丢过一次，靠 `git diff` 才发现）。两份同义文本，改一处忘一处就是静默失效。

严重度四档的问题是没有消费者。四档要求每条结论都标，但主管审 diff 时读的是 diff 本身；「阻断」与「必须改」的区别要靠 merge 是否被允许体现，而 merge 侧只认 `review` 状态与六项机械检查。四档里只有两档产生不同动作。

## 被否决的替代方案

| 方案 | 否决原因 |
| --- | --- |
| 反过来删 brief 的自审节、只留 prompt | brief 是 worker 的唯一事实来源，它要能独立读懂；prompt 只在启动时注入一次，翻不回去 |
| 保留四档但规定「阻断与必须改同义」 | 同义的档位就是噪音，规范里写「这两个一样」比删掉更费解 |
| 严重度只留一档 | 会失去「建议」这个分流：可另开任务的问题需要有地方放，否则要么塞进必须改拖慢合并，要么丢掉 |

## 影响范围

- 涉及文件/模块：`foreman.py`（`worker_prompt` 第 3 条、`brief_text` 严重度行、`manual_items`）、`orchestration.md` 审查节
- 实测变化：prompt 1063 → 901 字符，每次派工注入体积减 174 字符，重复文本归零
- 后续约束：自审要求再改只改 brief 一处；新增严重度档位须先指出它与现有两档的动作差异
- 未处理（待单独裁决）：决策记录门槛、双预算的单行字符上限、handoff 必写
