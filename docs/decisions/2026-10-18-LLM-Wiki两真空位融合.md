# LLM Wiki 两真空位融合（Query 回填 + 知识健康 Lint）

- 日期：2026-10-18
- 状态：已生效
- 相关模块：`skills/vibe-memory/SKILL.md` + references/decision-writing.md、`skills/vibe-governance/SKILL.md` + references/governance-review.md、assets/AGENTS.md §6、assets/docs/design/governance-retrospective.md

## 决策内容

将 LLM Wiki 模式经第一性检验后有价值的两个真空位融入体系：①**Query 回填**——会话产出的重要分析按收敛度路由（到选型点→决策记录；未收敛但可复用→design/ 分析文档带状态标注；无复用价值→不留），路由细则入 vibe-memory；②**知识健康 Lint**——文档间矛盾/过期引用/孤儿文档三查入 vibe-governance 复盘症状收集，新增第 6 条复盘信号并同步 retrospective 正本。**不融**：index.md 全量目录（反模式 #7 膨胀风险，规模信号出现再评估）、log.md 时序流水（与"快照是状态"哲学相抵，git log + progress 日期前缀已覆盖）、raw sources 层（软件项目真相源=代码，不适用）。

## 选择理由

- 第一性检验通过：Query 回填——决策记录只收"有结论的"分析，未到决策点的探索无家可归，是"理由埋在聊天记录"痛点的残留盲区；知识 Lint——§6 同步规则只管代码↔文档，没人管文档↔文档，决策被推翻后下游引用不受控。两者删掉都会让 Agent 重复调研或按过时文档犯错。
- 治理与性价比（用户约束）：常驻层净增 0 行（仅 §6 design 行改半句）；细则层净增约 10 行按需加载；无新目录、无新技能、无新工具。清单不复制（信号正本仍留 retrospective）。

## 被否决的替代方案

| 方案 | 否决原因 |
| --- | --- |
| 新建 docs/research/ 目录承载分析产物 | 目录+1 即治理面+1；design/ 经一行描述扩展即可承接，路由规则比新容器轻 |
| 全量 index.md 内容目录 | 查询入口 grep+决策索引在当前规模够用；索引膨胀即反模式 #7 重演 |
| log.md 时序流水文件 | 与"快照是状态不是日志"核心哲学相抵；其可 grep 价值已被 progress 日期前缀与 git log 覆盖 |

## 影响范围

- 涉及文件：vibe-memory（路由表+1 行、decision-writing +1 节）；vibe-governance（信号 6 条、description、governance-review 三查 + "5 信号"措辞改中性）；assets AGENTS.md §6（design 描述+半句）；retrospective 信号正本（5→6 条）；`~/test` 同步两处。
- 兼容性：既有语义不变；信号清单数字措辞改中性以防漂移。
- 后续约束：决策索引超一屏（既有信号 2）出现时，重评估全库 index.md；分析文档被推翻时按知识健康三查回头更新引用。
