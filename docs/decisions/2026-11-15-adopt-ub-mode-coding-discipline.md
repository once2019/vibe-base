# 吸收 ub-mode 的编码纪律：新增细则层，不动红线

- 日期：2026-11-15
- 状态：已生效
- 相关模块：`skills/vibe-base/assets/docs/governance/coding-discipline.md`（新）、`AGENTS.md` §3、`docs/governance/orchestration.md`「重派阶梯」

## 决策内容

把 `unclebob/ub-mode`（MIT，152 行单文件）中 `AGENTS.md` §3 未覆盖的编码纪律，改写成本仓口径的 `docs/governance/coding-discipline.md`，`AGENTS.md` §3 留一行指针，编排的「重派阶梯」接上其中「两次失败后攻击前提」。

不引入 ub-mode 的技能形态，也不引入它的三个质量门槛工具。

## 选择理由

- ub-mode 的定位是纯编码纪律，vibe-base 已有治理骨架与执行编排，两者是上下游而非替代关系。ub-mode 没有记忆、决策、Ask-first、并行隔离，vibe-base 没有「修还是重设计」的判断口径。
- §3 九条已覆盖 ub-mode 的一半：最小代码、外科手术式修改、可验证目标、可判定、不推断、完整性不靠抽样。重复的部分不收。
- 真正缺的六条有判据，能落进项目：不硬接旧设计（判据是特殊分支里出现设计文档没有的名词）、两次失败后攻击前提（判据是同一道门）、非法状态写不出来（结构表达约束）、幂等（跑两次终态相同）、共享状态单写者（结构强制）、测行为不测实现（所有函数返回空测试还能过就删）。
- 放细则层而非 §3：§3 只剩 7 行预算，六条塞不进；vibe-base 的分层原则本来就是常驻层放红线、细则层放操作条文。实测 §3 增 1 行后 94/100。
- 质量门槛（CRAP < 10、重复率 < 0.8、变异测试）单独列为「可选」，因为三个工具要装（Ask-first），不装也能按判据人工检查。
- 与编排的咬合点只有一处：第三次重派前先写前提。这条把 ub-mode 的「攻击前提」从编码层接到编排层，`blocked` 的交接说明因此有内容要求。

## 被否决的替代方案

| 方案 | 否决原因 |
| --- | --- |
| 把 ub-mode 作为第二个技能并列安装 | 用户已明确只装一个技能；两份编码纪律会漂移，且 ub-mode 的 push 策略与本仓相反 |
| 把六条全塞进 `AGENTS.md` §3 | 超 100 行预算；红线层不该放操作细节 |
| 默认启用 crapper / dryer / mutator | 属 Ask-first 的系统级依赖，且与「纯标准库、零依赖」的卖点冲突 |
| 照搬 ub-mode 的「最后推到主线」 | 与本仓「合并后不自动 push，人保留最后决定权」相反，细则里显式声明覆盖 |
| 照搬 ub-mode 的「Keep a Log」原样 | 本仓已有 evidence 与竣工单，只保留「一行日志随竣工单报」这一层，不新增日志格式 |

## 影响范围

- 涉及文件：`skills/vibe-base/assets/docs/governance/coding-discipline.md`（新，66 行）、根 `docs/governance/coding-discipline.md`（符号链接）、`AGENTS.md` §3（+1 行）、`orchestration.md`「重派阶梯」（+2 行）、`SKILL.md` 与 `README.md` 的文件数（16→17）
- 兼容性影响：`init` 自动扫描 `assets/`，新文件随骨架落地，无需改枚举；已初始化过的项目要 `--force` 或人工复制才会拿到这份细则
- 后续约束：编码纪律的正本是这份细则，`AGENTS.md` 只留指针不复述；再吸收 ub-mode 的新条文先比对 §3 是否已覆盖，避免两份说法

## 审查修订（2026-11-15）

五轴复审后改了七处：

1. 「移除那个赋值」是误译。ub-mode 原文 `Remove the assignment` 指职责分配，不是赋值语句，改成「撤掉那处职责分配或那层依赖」。
2. 「数哪个 actor 持有失衡」改成「清点哪一方承担了不平衡」，去掉生硬的 actor。
3. 不硬接的判据原本依赖「设计文档」，很多项目没有或不完整，改成「既有代码和文档里都找不到」。
4. 与编排的衔接写错了：原文说「没写出来之前不派第三次」，与三次上限冲突。改成第三次派工前把前提写进 `--retry-note`，写不出才转 `blocked`。
5. 「收尾」一节复述了 §6 提交纪律、worktree 清理与 push 策略，违反权威文档唯一。压成指针；push 策略属编排，补进 `orchestration.md` 的合并命令注释（`merge` 不 push）。
6. 「每个动作记一行日志」与 §5「快照只记当前状态，留着就退化成流水账」张力。改成「长任务记动作日志，完成时归入竣工单，不新增常驻文件」。
7. 两处与 §3 对齐补显式说明：「重设计也分片、每片按最小改动」「造工具没到第三次不造」，避免看起来像在推翻最小代码。

另加交叉引用三处（§5 记忆归属、§3 可验证目标、§6 提交纪律），并把 dryer 的 0.8 标注为未实测的默认阈值。
