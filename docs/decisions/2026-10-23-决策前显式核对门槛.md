# 决策前显式核对门槛（软约束改报告义务）

- 日期：2026-10-23
- 状态：已生效
- 相关模块：`AGENTS.md`、`skills/vibe-base/assets/AGENTS.md`、`docs/decisions/README.md`、`docs/governance/decision-writing.md`

## 决策内容

「修改某模块前先查决策索引」由软约束改为显式报告义务：动手前检索 `docs/decisions/`，回复中必须报告命中条目及冲突情况，未命中须声明「决策库无相关条目」，无报告视为违反红线（AGENTS.md §5，§7 执行阶段同步）。索引行增设模块字段，作为模块维度检索的分组依据（单一列表，不建分组小节）。

## 选择理由

- 解决的问题：实测失败模式——用户反馈 Agent 做决策时不主动查历史决策。三个成因叠加：规则埋在长文靠自觉、检查点（会话启动读 3 条）与真实决策时点（写方案瞬间）错位、「查没查」无留痕不可审计。
- 相比现状的收益：报告义务把隐性动作变成显式输出，用户可见、可当场纠正；未命中也须声明，堵住「没查所以不说」的漏洞。与 2026-10-22 复盘决策「规则价值在事后可判定而非事前拦截」一脉相承，是可判定性的补全。
- 约束：L1 预算 88/100 行、单行 ≤200 字符——改写 §5/§7 既有行、不新增行；索引行加字段属格式微调，decision-writing.md 同步一处格式说明。
- 可逆性：改回 §5/§7 两行原文并删索引模块字段即撤销，数分钟内可重建。

## 被否决的替代方案

| 方案 | 否决原因 |
| --- | --- |
| 代码侧反向指针（模块入口文件登记决策指针） | 每次决策新增一条同步义务，指针漂移即误导后来者；用户本次未选，留观察 |
| 索引建分组小节 | 同一决策双登记（主列表 + 小节）违反写入前查重；「最近 3 条」跨组语义模糊；行内模块字段对 grep 检索等效且零增量维护 |
| 脚本门禁强制拦截 | 与 2026-10-22 复盘决策否决理由相同：门禁引入执行成本与误报，模型不遵守时脚本替代不了判断 |
