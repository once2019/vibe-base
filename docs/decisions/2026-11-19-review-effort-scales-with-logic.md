# 自审随改动分级，完成定义按目标达成

- 日期：2026-11-19
- 状态：已生效
- 相关模块：`docs/governance/coding-discipline.md`（单会话最低审查口径）、`docs/governance/orchestration.md`（派工单判据）、`orchestration-doctrine.md`（完成定义）、`scripts/foreman.py`（派工单自审第三步与完成定义节）
- 承接：`2026-11-19-gate-failure-is-not-task-failure`

## 决策内容

**1 反证按改动分级。** 本次 diff 动了条件表达式、断言、边界比较、错误分支时做反证；纯文档、文案、常量、重命名、注释的改动免做，交付说明写一行「无逻辑改动，反证豁免」。拿不准就做。

**2 完成定义按目标达成。** 完成 = 目标达成 + 已知偏差留痕。验收命令是主要证据而不是全部定义；遗留项按可直接派单的形态列出，带遗留交付算正常完成。遮挡遗留或把偏差说成通过才算失败。

## 选择理由

前一条决策解决了「门失败怎么办」，没解决「每次都要全跑」。反证原先写成「DONE 前的强制项」，一段文案改动也要取反一个条件跑测试，把注意力从完成任务移到凑齐检查。同理，`--accept` 原先是完成定义的唯一内容，一条命令没过就等于任务没做完，遗留项只能以失败形态出现。

分级判据选「有没有动逻辑」而不是「改了几行」：行数不决定风险，条件与断言才决定。豁免要求写一行标记，所以跳过了什么是可核对的。

## 被否决的替代方案

| 方案 | 否决原因 |
| --- | --- |
| 按 diff 行数分级 | 行数与风险无关：一行 `if` 的条件取反比五十行文案危险 |
| 彻底取消反证 | 它是唯一能把「我测过了」变成可审计产物的动作，实测抓到过真缺陷 |
| 验收命令降为建议 | 没有命令就没有锚点，`review` 的 `acceptance` 检查会失效 |
| 遗留项另立字段 | 交付说明与竣工单已经承载；新增字段没人读 |

## 影响范围

- 涉及文件：`coding-discipline.md`、`orchestration.md`、`orchestration-doctrine.md`、派工单（自审第三步与完成定义节）、测试 5 项
- 兼容性影响：无命令与状态机变更；`review` 仍跑 `acceptance`
- 后续约束：反证豁免必须在 DONE 里写明；带遗留交付要在竣工单里列成可派单形态
