## 真实通道 E2E（2026-11-13，Orca，`/tmp/e2e-skill`）

两轮全链路跑通：`init` → `task new` → `dispatch`（Orca 托管 worktree，worker=pi）→ 等 DONE → `review`（6 项自动 + 五轴人工 + 反证）→ `merge`（--no-ff、复跑验收、删树归档）→ `report`（竣工单入 docs/progress/）。worker 真实改了代码、自己提交、自审四项写在 DONE 正文里。

暴露 4 个问题，全部已修（测试 114→117）：

1. **`worker_done` 缺 `--task-id` 被 Orca 拒收 → 主管静默超时**。拒收后 subject 变成 `Rejected worker_done: [FOREMAN:DONE] ...`，协议头正则匹配不到，被当成"非协议消息"跳过。修：派工 prompt 把 `--task-id` 写成必填步骤（先 `worker-list` 取 taskId）；`wait_message` 识别 `Rejected` 前缀返回 `rejected` 信号，`events` 直接报错并给处理指引。
2. **Orca 模式发送者校验误报「疑跨仓串线」**。Orca 的 `from` 是终端句柄 `term_*`，dispatch 记的是 `dispatch:ctx_*`。修：orca 模式下 `term_*` 视为正常（hcom 侧校验不变）。
3. **`report` 不校验状态**：`merge_ready` 也能往 `docs/progress/` 写竣工单，会被当成已完成。修：非 `completed` 直接拒绝。
4. **主管手工 `check --json` 会吃掉 worker 的 DONE**（消费式）。修文档：排查用 `--peek`，收信一律走 `events`。

副产物：`/tmp/e2e-skill` 已注册进 Orca（`orca repo` 无 remove 命令），worker 已全部 stop。
