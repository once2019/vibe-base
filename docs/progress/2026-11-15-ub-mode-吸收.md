## 评估结论

ub-mode 是纯编码纪律，三层：先让它能跑、再让它对、按实践收尾。与 vibe-base 是上下游关系，不构成替代。

§3 九条红线已覆盖它的一半：最小代码、外科手术式修改、可验证目标、可判定、不推断、完整性不靠抽样。

真正缺的六条，各有判据，已收进细则：

| 条文 | 判据 |
| --- | --- |
| 不硬接旧设计 | 特殊分支里出现设计文档没有的名词 |
| 两次失败后攻击前提 | 两个修法共享前提且在同一道门失败 |
| 非法状态写不出来 | 约束用结构表达，不用注释与运行时检查 |
| 幂等 | 跑两次或中途崩溃后重跑，终态相同 |
| 共享状态单写者 | 结构强制，不靠约定 |
| 测行为不测实现 | 所有函数返回空值测试还能过就删 |

冲突一处：ub-mode 要求"最后推到主线"，本仓是"合并后不自动 push，人保留最后决定权"。细则里显式声明本仓口径覆盖。
