# vibe-template

给 AI 编程 Agent 用的协作规范，以三个技能交付。设计不是拍脑袋来的：主体来自 Karpathy 的三套公开理念，经一个真实项目五十四次决策的实战打磨后固化成型。本文先讲理念，再讲怎么落进体系，最后是使用方法。

## 三套底层理念

这三套都出自 Karpathy 的公开写作，各管一层：Agent 的行为、知识的积累、沟通的质量。

### Guidelines：治 Agent 写代码的常见病

Karpathy 观察 LLM 写代码的翻车姿势，归结成四条规则：

- 动手前把假设说清楚。多种理解并存时全部摆出来，别偷偷挑一个。
- 只写解决问题的最小代码。没人要的抽象、配置项、"以防万一"的异常处理，一律不加。
- 外科手术式修改。每一行变更都能追溯到用户的请求；不顺手"改进"旁边的代码，既有死代码看见了要说，但不动手删。
- 先定义怎么算完成，再动手。修 bug 就先写复现测试，重构就保证前后测试都绿。

这套东西里更值钱的其实是元设计：规则必须来自实测的失败模式，不能从理想实践往下推；每条规则要配一个能自查的问题（"这行改动是用户要的吗？"）；每条规范要承认自己的代价，比如"偏向谨慎，牺牲速度"。

### LLM Wiki：知识要编译，不要每次现查

大多数人用 LLM 处理文档是 RAG 的路子：问一次，查一次，拼一次，什么都没留下。Karpathy 的说法是反过来——让 LLM 把知识"编译"进一个持续维护的维基。新资料来了不是建索引完事，而是读透、摘要点、更新相关页面、标出新旧矛盾；你查询得到的分析也回填进维基。输入和探索都在复利。

这套模式有三个动作：消化新源，查询回填，定期体检（抓矛盾、过期、孤儿页）。它成立的前提就一条：知识库不是死于没人读，是死于没人维护，而维护恰恰是 LLM 不嫌烦的那部分工作。

### 受控文字：沟通也要有硬约束

空客的维修手册用一套叫 ASD-STE100 的受控英语：句长有上限，一个动词只许一个意思，歧义词禁用。Karpathy 拿它说明一个趋势：LLM 越强，人的工作越往"理解"上移，而理解的介质是可以换的——从受控文字，到图，到交互网页，再到按需生成、用完即弃的讲解视频。

落到编程协作，最直接的是前半段：Agent 跟人的沟通也该受控。同一个概念只许一个名字，一句话只说一件事，"尽快处理"必须换成具体日期。

## 怎么落进体系

三套理念没有做成第四个技能，而是按"红线常驻、细则按需"分层塞进现有结构。行为红线每次会话都生效，不赌语义触发；写作细则只在动笔时加载，不占平时上下文。

| 理念 | 常驻层（AGENTS.md，每次会话生效） | 细则层（技能，写作或治理时加载） |
| --- | --- | --- |
| Guidelines | §3 四条行为规则 | vibe-governance 的收录铁律，三条元设计管规则演化 |
| LLM Wiki | §6 文档目录给分析产物留了家 | vibe-memory 的回填路由；复盘信号新增知识体检 |
| 受控文字 | §3 沟通受控一行 | decision-writing 的行文受控节 |

有些东西明确不搬。LLM Wiki 的全量目录页在百来个文件的项目里是纯负担；时序日志文件和"快照是状态不是日志"的原则相抵，git log 已经管了时序。缺什么补什么，不整套照搬。

## 解决什么问题

### 会话一长，Agent 就失忆

上下文满了，开个新会话，Agent 把上周定的方案忘得一干二净。你重新解释一遍，它重新问一遍，一周下来你怀疑自己是在编程还是在给 AI 补历史课。

模板用三层记忆对抗上下文丢失：L1 = `AGENTS.md`，常驻，只放红线和目录；L2 = `docs/decisions/`，每个技术决策一条记录，含理由和被否决的方案；L3 = `docs/memory/`，当前状态快照加跨会话交接。新会话先读快照，再查决策索引最近三条，然后动手。上下文不用记住所有事，只需要知道去哪查。

### 决策的理由埋在聊天记录里

"当时为什么用轮询不用 WebSocket？"答案在三天前的对话里，没人翻得动。下个会话的 Agent 看了眼代码，觉得 WebSocket 更优雅，推翻了它，没人意识到这是重复踩坑。

决策记录强制留痕：决定了什么、为什么、否决了什么、影响哪里。四天实战里这个机制接住了五十四条决策。现在连没走到决策那一步的调研分析也有去处：方案比较、根因分析、踩坑发现，落进 `docs/design/` 带上状态标注，下次直接查。

### 规则写了好几遍，互相矛盾

`.cursorrules`、`CLAUDE.md`、copilot 的说明文件，再加一段贴在 prompt 里的。四处规则，改一处漏三处，Agent 读到哪份算哪份。

`AGENTS.md` 是唯一事实来源。规则只收 Agent 读代码发现不了的信息，每行先过一遍：删掉它，Agent 会犯错吗？不会，就删。

### Agent 说"完成了"，其实没跑

"已修复。"测试没跑，lint 没过，类型检查一片红。你信了，合并了，CI 教你做人。

规范写死：提交前检查全部通过，禁止跳过验证直接宣称完成，必须贴命令输出当证据。测试全绿只证明能跑，不证明对。

### 代码改了文档没动，文档之间还互相打架

接口签名变了，`docs/design/` 里还是三个月前的图，Agent 照旧文档写新代码，错得理直气壮。更隐蔽的是文档之间的矛盾：一个决策被推翻了，引用它结论的另外三份文档没人记得改。

同步规则写进流程，复盘信号里加了知识体检：矛盾、过期引用、孤儿文档，查到就修。

### 沟通驴唇不对马嘴

Agent 这个会话管某个机制叫 A，下个会话叫 B，你 grep 都对不上。"尽快优化一下"这种话，Agent 和你各自理解成了两件事，返工。

沟通受控的一词一义管前者：概念命名随决策产生，全库沿用，改名要走决策。结论先行、一句一义、模糊量词必须落成具体数字，管后者。

### AI 生成的代码没人评审就进主干

Agent 十分钟写了五百行，看着挺像回事。没有人类评审，合并，上线，出事。

红线钉死：AI 生成的代码未经人类评审不得合并或部署；认证、加密、输入校验一律用成熟库；删数据、force push、改 CI 这类危险操作，执行前必须人点头，全部集中在 `AGENTS.md` §4 的清单里。

### 上下文被历史堆满

把所有过往对话堆进上下文，token 烧得飞快，关键信息还被淹没。

记忆按需分层加载：快照只记当前，完成项移交 `docs/progress/` 后即删，决策索引只留最近三条文件名，行数和单行长度都有硬上限。快照是状态，不是日志。

## 使用方法

安装三个技能到用户技能目录：

```bash
mkdir -p ~/.codebuddy/skills && cp -r skills/vibe-init skills/vibe-memory skills/vibe-governance ~/.codebuddy/skills/
```

新项目说一句「初始化项目治理」或「init AGENTS」。vibe-init 生成骨架：幂等，不覆盖已有文件；占位符不追问，Agent 在后续开发中获知实际信息后自己回填。

之后不需要你操心运转。Agent 写文档时 vibe-memory 的细则会介入，治理信号出现时 vibe-governance 接管，行为红线由 AGENTS.md 常驻保证——这套机制不依赖任何技能被"想起来"。

## 好处与代价

好处：新项目冷启动一句话得到一套完整规范；跨会话不失忆、不重复踩坑；每条规则有证据、能自查、可演化；文档之间的矛盾会被定期体检抓出来。

代价也说清楚：AGENTS.md 常驻 86 行（上限 100）；细则加载和自查会拖慢写作节奏；证据门槛会否决一部分"感觉对"的改进。这套体系偏向正确而不是速度，琐碎任务凭判断简化。

## 仓库结构

```text
├── AGENTS.md               # 本仓库自身的协作规范（非模板）
├── README.md               # 本文件
├── docs/decisions/         # 本仓库自身的决策记录
└── skills/
    ├── vibe-init/          # 治理骨架初始化：SKILL.md + assets 模板唯一正本 + scripts 脚手架
    ├── vibe-memory/        # L2/L3 写作细则：context/handoff/决策记录怎么写才合格
    └── vibe-governance/    # L1 维护与治理复盘：规则怎么改、复盘怎么跑
```

## 修改纪律

- 改模板 = 改 `skills/vibe-init/assets/` 下的文件；模板规则变更须先在 `docs/decisions/` 登记决策记录。
- 提交前验证：脚手架在临时目录两遍运行（新建 + 幂等）通过，且官方 `package_skill.py` 校验通过；展示命令输出。
- 规范细节见本仓库 `AGENTS.md`。

## 这个模板长这样，是复盘出来的

模板在真实项目实战一周（54 条决策）后做了一轮治理复盘：8 个反模式（入口膨胀、压行不压量、规则相抵、决策无索引、Ask-first 散落、易腐运行态、bootstrap 膨胀、不可测触发）各有实测证据与改法，已全部固化进模板本体。证据与自查清单见 `skills/vibe-init/assets/docs/design/governance-retrospective.md`。

## 这个模板不做什么

不规定技术栈，不替你写代码，不保证 Agent 不出错。它只解决"人和 Agent 如何跨会话协作"这一层：记忆不丢、决策可查、规则唯一、验证留证、沟通无歧义。代码质量由你的评审把关，这是红线里唯一不能被自动化替代的部分。
