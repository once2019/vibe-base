# 编码纪律（§3 的操作条文）

> 来源：`unclebob/ub-mode`（MIT）中 `AGENTS.md` §3 未覆盖的部分，按本仓口径改写。
> 读它的条件：判断这次改动是修还是重设计、同一道门连续失败两次、或要决定质量门槛时。
> §3 是红线，本文件是操作条文；冲突以 `AGENTS.md` 为准。与 §3 同源的条目会标出对应条款，不另立说法。

## 三段顺序

先让它能跑，再让它对，最后按实践收尾。跳段的代价是：对的结构建立在错的形状上，之后每次改动都要付利息。三段都按最小改动走，"能跑"不等于"先随便写"。

## 不把新需求硬接到旧设计上

新需求与既有设计的形状不合时，先问"如果一开始就有这个需求，会怎么建"，想清楚再分片交付。

判据：这次改动要给旧结构加一个特殊分支，而分支里出现的名词在既有代码和文档里都找不到，就是硬接。

同一个功能在第二个应用点出现第二份实现（两份只差参数或调用方），是把不同时间点的改动叠成了两套设计。判据：要复制一段既有逻辑再改两行，就是该收敛的信号。

收敛前先查历史：`git log -- <路径>` 看这块过去怎么演化的，`docs/decisions/` 看有没有相关决策。同一处被改过三次，说明设计没跟上需求，该重设计而不是第四次加分支。把历史改动与新需求一起收成一套设计（一个入口、一份实现、参数化差异），再分片交付。

重设计同样分片交付，每片按最小改动走（§3「只写解决问题的最小代码」）。

## 两次失败后攻击前提

两个修法共享同一前提，又在同一道门（同一测试、同一验收命令）失败时，停下来做四件事：

1. 把那个前提写成一句话。
2. 清点哪一方承担了不平衡：谁多做了一步，谁少做了一步。
3. 撤掉那处职责分配或那层依赖，而不是再加一层判断。
4. 前提没写下来之前，不开第三个修法。

这条接在编排的第三次重派之前：前两次修实现，第三次先把前提写进 `--retry-note`；写不出前提就转 `blocked`，不再派。

## 让非法状态写不出来

- 用结构表达约束，不用注释和运行时检查。枚举代替字符串，必填项进构造函数，互斥字段合并成一个类型。
- 外部数据在入口解析一次，内部信任解析结果；业务逻辑写成纯函数。
- 不压制编译器的报错。类型错误是信息，压下去等于把问题推迟到运行期。

## 幂等

跑两次、或中途崩溃后重跑，终态相同。写状态、建资源、发通知都按这个标准检查。做不到就加显式前置判断（已完成则跳过），不靠"调用方只会调一次"。

## 共享状态先分离再串行

不需要共享的可变状态，各自持有一份。必须共享时只允许一个写者，并在结构上强制（独占写入权、单线程消费），不靠约定。

本仓的实例是 §5 的记忆归属：`docs/memory/` 由主管独占写入，worker 不写。

## 测试行为，不测实现

测试的调用方式与真实使用者一致，断言使用者能看到的结果。判据：如果所有函数都改成返回空值、测试还能通过，这个测试就该删。

这是 §3「实现前把任务转译为可验证目标」的展开：前者管测试写什么，这条管测试怎么断言。

## 不显然的活先造工具

同样的手工操作做到第三次，停下来造工具。做法：先手工完整做一个单元，再让工具产出与那个单元逐字一致的结果，之后交给工具。

没到第三次不造，避免为一次性的活提前抽象（§3「只写解决问题的最小代码」）。

## 收尾

- 长任务记动作日志（做了什么、为什么），完成时归入竣工单，不新增常驻文件（§5：快照只记当前状态，留着就退化成流水账）。
- 主线程只留结论与指针，大块分析外包，回来的只要摘要。
- 提交纪律见 §6；清理与 push 的机制见 `orchestration.md` 的合并流程与 `doctor` 的 `resource-leaks`。

## 可选质量门槛

三个工具（`unclebob/crapper`、`unclebob/dryer`、`unclebob/mutator`）装在机器级，不进项目依赖也不进 git，首次运行自己建 `.venv`。装它们属 `AGENTS.md` §4 的"安装系统级依赖"；不装也能按下面的判据人工检查，装了才有机械证据。

| 工具 | 看什么 | 命令 |
| --- | --- | --- |
| crapper | 复杂度热点与 CRAP 分数 | `~/tools/crapper/crapper <目录>...` |
| dryer | 结构重复候选 | `~/tools/dryer/dryer <目录>...` |
| mutator | 变异点与存活数 | `~/tools/mutator/mutator --scan <文件>` |

CRAP = CC² × (1 − 覆盖率)³ + CC。1 到 5 低风险，5 到 30 值得看，30 以上复杂且覆盖不足。分数需要覆盖率：crapper 只读 `coverage/lcov.info`，没有它时只出 CC，Cov% 与 CRAP 显示 N/A。

重复度默认阈值 0.82，达到即列为候选。候选不等于该合并，结构相似但职责不同的代码合并后更糟，要人工判断。

变异测试一个文件几十个点，每个点跑一次测试，按改动的文件跑，不全量。存活的变异体是缺测试的证据，补测试或删死代码。

两个工具的坑：不传目录时会向上找根，可能扫到项目外的文件，一律显式给目录。产物落在 `.metrics/`，加进忽略规则。

`doctor` 的 `quality-tools` 检查机器上装没装：缺了报 WARN 不报 FAIL，不影响退出码，因为它是可选门槛。
